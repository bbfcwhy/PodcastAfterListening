# 語音轉文字模型評估（2026-10-06）

適用兩個情境：

- **情境 A：好味小姐**（公開節目，目標是大量轉錄、可以搜尋「哪一集聊過什麼」）
- **情境 B：曼報 Pro「商業解碼」**（付費內容，只給威爾個人用；目標是分出 4 位講者，財經術語要準）

要打贏的基準：**FunASR Paraformer-large + cam++**。之前用它跑過 40 集好味小姐，威爾的評價是「實在不是很準」，四類問題都有：① 講者分錯人 ② 一般口語聽錯 ③ 專有名詞錯 ④ 斷句和時間戳亂。

> ⚠️ 這份是文獻研究，還沒實測。下面的準確度數字都是各家自己公布的成績，測試資料是朗讀或會議錄音，不是台灣閒聊型 podcast。最接近脫口秀的 Formosa-Show 測試集上，連最好的 Breeze 錯誤率都有 27.58%。哪個真的比較好，要用同一段音檔並排比對才知道（見第 6 節）。

硬體（實測）：Apple M1 Max，64 GB 記憶體，macOS 26.7.1。

---

## 1. 結論

1. **轉錄本身已經可以做到全本機、免費。** 前幾名都是 Apache-2.0 或 MIT 授權，可以用 Mac 的 GPU（MLX）跑。之前所有轉錄都跑在 CPU 上（`PAL_AIAnalyzeLocal/batch_transcribe_funasr.py:152,160`），沒用到 GPU。
2. **整體首選：Qwen3-ASR-1.7B（MLX 版）配 pyannote community-1 分講者。** 在台灣華語朗讀測試集上錯誤率 3.77%，Whisper large-v3 是 7.84%。可以指定講者人數，也能給術語提示。缺點是輸出簡體，要用 OpenCC `s2tw` 轉成繁體，再補三條修正（見第 4 節第 4 點）。在唯一一份同一測試集的中文對照（GigaSpeechBench，見第 3.1 節）裡，它也是第一名。
3. **挑戰者：Breeze-ASR-25（聯發科）。** 它是唯一有中英夾雜測試數字的候選：13.01%，Whisper-v2 是 29.49%。直接輸出繁體。底層還是 Whisper，所以幻覺風險跟著來。
4. **講者辨識沒有銀彈。** 講者越多越難分：2 人到 4 人，錯誤率大約翻倍。所有開源工具都沒有內建「先錄一段聲音註冊講者」的功能，一定要指定講者人數。
5. **專有名詞靠詞彙表，但 LLM 校正要「限制型」。** 有研究發現，直接叫 LLM 改逐字稿，錯誤率反而從 12.42% 升到 22–33%。正確做法是只准替換詞彙表上的詞，並列出改了哪裡。

## 4. 關鍵注意事項

1. **講者人數要明確指定。** pyannote 在 CALLHOME 測試集上，2 人時錯誤率 10.00%，4 人時 21.19%。FunASR 可以輸出每位講者的聲紋平均值（`return_spk_center`），想做「聲紋註冊」要自己寫比對程式。
2. **詞彙表校正要限制型。** 硬塞不相關的熱詞也有副作用：有人實測時，「李主任」被憑空插入 14 次，處理時間從 72 秒變成 401 秒。
3. **私人內容不用 Gemini 免費版。** 付費版不拿去訓練，一集 60 分鐘大約 11.5 萬 token，推估不到 0.5 美元。Groq 免費版也不拿去訓練，但它只有 Whisper，沒有講者辨識。
4. **繁簡轉換用 `s2tw`，不要用 `s2twp`。**（曼報 session 2026-09-12 踩過的坑）
   - `s2twp` 除了換字，還會換詞，例如「文件→檔案」「參數→引數」。講者本來就講台灣用語，ASR 是照發音寫字，詞換了反而改錯講者原話。
   - 做法：先跑 `s2tw`（只換字），再補三條修正：臺→台、瞭解→了解、控制檯→控制台。
   - 驗法：轉完用 `s2t` 再掃一次，剩下的命中應該只有「才、台、了、群」這幾個刻意保留的字。

## 5. 不用下載就能改的兩件事

1. **mlx-whisper 的 `--hallucination-silence-threshold` 要搭配 `--word-timestamps True` 才會生效。**
   【已在本機驗證】`mlx_whisper/transcribe.py:414` 是 `if word_timestamps:`，防幻覺的邏輯在 `:432`，包在這個條件裡面。曼報 session 目前的指令沒加 `--word-timestamps True`，所以這個參數其實沒有作用。
2. **FunASR 現有流程可以補兩個參數**（研究員讀原始碼得知，我沒有在本機驗證）：
   - `hotword="..."`：`paraformer-zh` 就是支援熱詞的版本（SeACo-Paraformer）。論文顯示熱詞召回率可從約 12% 提升到 60–65%。
   - `preset_spk_num=N`：指定講者人數。

## 6. 實測計畫（威爾 2026-10-06 決定先不實測，留著日後參考）

**素材**：本機都有。
- 音檔：`~/Projects/PAL_AIAnalyzeLocal/data/audio_files/`
- 舊的 FunASR 輸出：`~/Projects/PAL_AIAnalyzeLocal/data/transcript_funasr/`（40 個 SRT）

**做法**：
1. 從一集已有舊輸出的好味小姐剪一段 15 分鐘，要包含英文詞、人名、一段靜音或配樂。
2. 用以下設定跑同一段：
   - 舊 FunASR 輸出（基準，直接拿現成的）
   - FunASR 加上熱詞和講者人數
   - Qwen3-ASR + pyannote
   - Breeze-ASR-25 + pyannote
3. 做一個 HTML 比對頁：上方放音檔播放器，下方把四份逐字稿按時間對齊並排。威爾聽 3–5 分鐘，逐類標出錯誤（① 講者 ② 口語 ③ 專有名詞 ④ 斷句），頁面自動算出每個方案在四類各錯幾處。
4. 曼報的 4 人講者辨識：用免費版曼報（Manny 和 Angela 主持）的一段做同樣的測試。這個節目清單還沒查證。

**要下載的東西**：
- Qwen3-ASR 1.7B：4.70 GB（8-bit 版 2.17 GB）
- Breeze-ASR-25 MLX 版：3.08 GB。這是第三方轉的版本，權重格式是 safetensors（只有數字，不含可執行程式）。如果要用官方原版，得下載 15.98 GB 自己轉換
- pyannote community-1：約 30 MB，要先在 Hugging Face 網頁同意使用條款
- 選配 VibeVoice-ASR 4-bit：5.71 GB，可能吃滿 64 GB 記憶體

**指令草稿**（研究員整理，還沒驗證過；`--model` 參數名稱要先看 README 確認）：

```
pip install "mlx-qwen3-asr[diarize]"
mlx-qwen3-asr clip.wav --model Qwen/Qwen3-ASR-1.7B --language Chinese --diarize --num-speakers N --context "<詞彙表>" -f all -o out_qwen
opencc -c s2tw.json -i out_qwen/clip.srt -o out_qwen/clip.tw.srt
mlx_whisper clip.wav --model c1ayvveng/Breeze-ASR-25-mlx --language zh --condition-on-previous-text False --word-timestamps True --hallucination-silence-threshold 2 --output-format all --output-dir out_breeze
```

## 7. 次要發現

- **好味小姐沒有現成的文字來源可撿。** Apple Podcasts 的自動逐字稿不支援中文，創作者也不能自己上傳中文逐字稿。YouTube 版有沒有自動字幕，研究員搜了 2 次沒找到。
- **呱吉「新資料夾」的資料庫**：網址是 https://sear.newfolderla.com/ ，叫「新資料庫」，可以逐句搜尋，還能跳回原音檔對照。轉錄用什麼工具，查不到。
  - 研究員推測：頁面程式裡有「校正」（含貢獻者、批次核准）和「詞彙表」的功能，所以他們應該是靠群眾校正加詞彙表，不是靠一個完美的模型。這點還沒驗證。
  - 2026-10-07 已查證校正與排行機制，見 `2026-10-07-讀者投稿校正與貢獻排行.md`。轉錄工具仍未查到。
- **What'sub（壹加壹 Lean 的字幕服務，2026-08 上線）**：官方沒公開模型，只說串接第三方雲端、多個模型分工。網友從網頁資料格式推測底層是 ElevenLabs Scribe，本人沒回應，屬推論。它沒有 API、官網沒寫講者辨識、最貴方案每月 6 小時，條款也沒明寫不拿去訓練，所以不列入候選，只把 Scribe 本身加進比較。來源：https://whatsub.equal2.app 、https://www.inside.com.tw/article/42420-lean-ai-vibe-coding-whatsub-subtitle-tool
- **網站目前搜不到逐字稿。** 逐字稿存在 `podcast_episodes.transcript`，但搜尋只查標題、摘要和心得（`supabase/migrations/003_functions_integrated.sql:48-53`），而且用 `simple` 設定，中文斷詞不好。
